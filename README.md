## Описание

Проект для оценки ассистивных функций цифровых сервисов по текстовым отзывам пользователей. К таким функциям относятся поддержка скринридеров, масштабирование текста, настройки контрастности и другие средства, которые помогают людям с особыми потребностями пользоваться приложениями.

Система анализирует отзыв и определяет критичность описанной проблемы доступности: низкую, среднюю или высокую. Отзывы без проблем доступности выделяются в отдельную категорию. Это позволяет находить барьеры в использовании сервисов и определять, какие проблемы требуют первоочередного исправления.

На сайте пользователь может проверить текст отзыва, вручную исправить предложенную моделью метку или добавить новый размеченный пример. Эти данные сохраняются для последующего дообучения: при запуске обучения они объединяются с исходным датасетом, после чего создаётся новая версия модели. Дообучение в проекте выполняется как повторное обучение на дополненном и исправленном наборе данных.

Для классификации используется собственная обученная модель на основе **TF-IDF и логистической регрессии**. Предсказания выполняются локально, без обращения к внешним LLM. Текущая модель предназначена для анализа отзывов на английском языке.

## Запуск и настройка

Для запуска необходимы **Python 3.12+**, **uv**, **Node.js 22+** и **npm**. Команды ниже выполняются в PowerShell из корня проекта, если не указано другое.

### Установка зависимостей

После скачивания проекта установите зависимости backend и frontend:

```powershell
uv sync --locked
npm --prefix frontend ci
```

`uv` создаст виртуальное окружение `.venv` и установит Python-зависимости из `uv.lock`. `npm ci` установит зависимости интерфейса из `frontend/package-lock.json`.

### Переменные окружения

Создайте файл `.env` в корне проекта из шаблона. Если `.env` уже существует, отредактируйте его, сохранив свои настройки.

```powershell
Copy-Item .env.example .env
```

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `RG_DATA_DIR` | `data` | Каталог датасетов, feedback и файла состояния backend. |
| `RG_API_ARTIFACTS_DIR` | `artifacts` | Каталог сохранённых моделей, метаданных и отчётов оценки. |

Например, если полный датасет сохранён в `data/reviews.csv`, укажите в корневом `.env`:

```dotenv
RG_API_INITIAL_DATASET=data/reviews.csv
```

Начальный CSV с диска импортируется при первом сохранении feedback или первом обучении, если датасет ещё не загружен через сайт. Загрузка CSV через сайт создаёт новую актуальную версию, которая используется для следующих обучений. Начальный файл не перечитывается при каждом запросе.

Если backend находится по другому адресу, создайте `frontend/.env.local`:

```dotenv
VITE_API_URL=http://127.0.0.1:8000
```

Переменные Vite применяются при запуске dev-сервера или сборке frontend. После изменения файла перезапустите frontend, а для готовой сборки выполните сборку заново.

### Первоначальная настройка через сайт

При первом запуске выберите один из двух вариантов настройки.

#### Вариант 1. Загрузить CSV и обучить модель

1. Загрузите через сайт полный размеченный датасет в формате CSV.

   Форма загрузки находится в разделе **«Обучение»**: выберите файл и нажмите **«Загрузить CSV»**. Используйте кодировку UTF-8 и запятую в качестве разделителя. После загрузки сайт покажет число отзывов и распределение классов. Дополнительные столбцы допускаются; одинаковые нормализованные тексты объединяются, а противоречащие метки дубликатов отклоняются. Загрузка нового CSV сохраняет накопленный feedback и не меняет активную модель до обучения.

| Столбец | Описание | Возможные значения |
|---|---|---|
| `text` | Текст отзыва пользователя о доступности сервиса. | Непустой текст на английском языке. |
| `label` | Класс критичности описанной проблемы доступности. | `no_issue` — проблема доступности отсутствует; `low` — небольшое неудобство, не мешающее пользоваться сервисом; `medium` — существенное затруднение при использовании отдельных функций; `high` — блокировка важного действия или недоступность сервиса. |

2. В разделе **«Обучение»** запустите тренировку модели. Датасет автоматически разделится на обучающую, валидационную и тестовую выборки — train, validation и test.
3. Дождитесь завершения обучения. Сайт покажет метрики оценки, а обученная модель сохранится и автоматически станет активной.

Отдельно загружать готовую модель при этом варианте не требуется.

#### Вариант 2. Загрузить готовую модель

1. Распакуйте архив с моделью. В нём должны находиться два файла одной версии: `model.joblib` и `metadata.json`.
2. Откройте раздел **«Модели»**, выберите оба файла и нажмите **«Загрузить модель»**.
3. После успешной загрузки модель станет активной и будет готова к анализу отзывов без повторного обучения.

Для предсказаний загрузка датасета не требуется. Если позже понадобится дообучение на собственных данных и сохранённых исправлениях, загрузите полный CSV.

Для тестового запуска можно использовать датасет или модель по ссылке [https://drive.google.com/drive/folders/1ewXCmJ7w5Np9iIb8HmkPouBnVbC0laY3?hl=ru](https://drive.google.com/drive/folders/1ewXCmJ7w5Np9iIb8HmkPouBnVbC0laY3?hl=ru)

## Дообучение и переобучение модели

Повторное обучение нужно, чтобы учитывать новые отзывы, исправлять ошибки разметки и адаптировать модель к формулировкам пользователей. Например, если модель определяет блокирующую проблему скринридера как небольшое неудобство, пользователь может указать правильный класс и сохранить этот пример для следующего обучения.

| Действие | Для чего используется | Что происходит в проекте |
|---|---|---|
| **Дообучение на новых данных** | Учесть новые примеры и исправления, внесённые пользователем на сайте. | Последний датасет объединяется с накопленными исправлениями, после чего модель обучается заново на обновлённых данных. |
| **Переобучение модели** | Повторить обучение на актуальном датасете, в том числе с другими параметрами. | Заново обучаются TF-IDF-векторизатор и классификатор, рассчитываются метрики и сохраняется новая версия модели. |

В этом проекте дообучение не является продолжением обучения сохранённых весов. Оба сценария используют полное повторное обучение Pipeline **TF-IDF + Logistic Regression**. При дообучении меняется состав или разметка обучающих данных.

### Как добавить данные и исправить ошибки

1. Откройте раздел **«Анализ отзыва»**, введите английский текст и запустите анализ.
2. Проверьте результат. Если класс выбран неверно, укажите правильное значение в поле **«Правильный класс»**.
3. Нажмите **«Сохранить для обучения»**. Чтобы добавить совершенно новый размеченный пример, достаточно ввести текст, выбрать класс и сохранить его — предварительное предсказание не обязательно.
4. Повторите эти действия для других отзывов. Также можно перейти к исправлению примера из списка ошибок, показанного после обучения.

Исправления накапливаются в отдельном файле `feedback.csv` рядом с актуальным датасетом. Повторное сохранение того же нормализованного текста обновляет его метку, а не создаёт ещё один пример. Изменение feedback не запускает обучение и не меняет предсказания текущей модели.

### Как запустить повторное обучение

1. Откройте раздел **«Обучение»**. При необходимости измените параметры:
   - **Seed** — значение для воспроизводимого разбиения данных и запуска обучения.
   - **C** — параметр, обратный силе регуляризации логистической регрессии: меньшее значение усиливает регуляризацию.
   - **Максимум итераций** — ограничение числа итераций оптимизации классификатора.
2. Нажмите **«Обучить модель»**. Последний датасет объединится с feedback: для уже существующего текста сохранённая пользователем метка заменит исходную, а новые тексты добавятся в набор данных.
3. Система сгруппирует похожие отзывы и разделит обновлённые данные на **train**, **validation** и **test**. Обучение векторизатора и классификатора выполняется только на train; validation и test используются для оценки.
4. Дождитесь завершения запроса. Во время обучения действия на сайте недоступны. После завершения появятся Accuracy, Precision, Recall, Macro-F1, матрицы ошибок и список неверных предсказаний.

Для разбиения необходимо не менее трёх независимых групп отзывов каждого класса. Если данных недостаточно или похожим отзывам назначены противоречащие метки, обучение завершится с сообщением об ошибке — сначала исправьте набор данных.

### Что сохраняется после обучения

После успешного завершения создаются новая версия объединённого датасета и новая версия модели с файлами `model.joblib`, `metadata.json` и отчётами оценки. Новая модель автоматически становится активной и используется для следующих предсказаний. Применённые исправления уже входят в новый датасет, а его файл feedback готов к накоплению следующих примеров.

Предыдущие версии датасетов и моделей остаются на диске. При ошибке обучения текущая модель продолжает работать, а накопленные исправления сохраняются для повторного запуска.

Добавление данных само по себе не гарантирует улучшения качества: важны правильность меток, разнообразие примеров и представленность всех классов. Оценивайте не только общую Accuracy, но и Macro-F1, Recall отдельных классов и матрицу ошибок. Для подтверждения улучшений используйте одну и ту же независимую проверенную тестовую выборку: результаты на заново разделённых данных напрямую сравнивать нельзя.

## Описание бэкенда

Бэкенд предоставляет REST API для анализа отзывов, сохранения пользовательских исправлений и повторного обучения модели. Он связывает интерфейс сайта с ML Pipeline, управляет версиями датасетов и моделей и возвращает результаты оценки.

При запуске сервер загружает последнюю сохранённую модель и использует её для предсказаний. После успешного обучения новая модель автоматически становится активной. Если обучение завершилось с ошибкой, предыдущая модель и накопленные исправления сохраняются.

### Стек

| Технология | Назначение |
|---|---|
| **Python 3.12+** | Язык серверной части и ML Pipeline. |
| **FastAPI** | REST API, обработка запросов, CORS и автоматическая документация OpenAPI. |
| **Uvicorn** | ASGI-сервер для запуска приложения. |
| **Pydantic** | Проверка структуры запросов, ограничений текста, классов и параметров обучения; описание ответов API. |
| **pydantic-settings** | Загрузка конфигурации из переменных окружения и `.env`. |
| **scikit-learn** | TF-IDF-векторизация, логистическая регрессия и расчёт метрик качества. |
| **joblib** | Сохранение и загрузка обученного Pipeline. |
| **python-multipart** | Обработка загрузки файлов модели через `multipart/form-data`. |
| **CSV и JSON** | Файловое хранение датасетов, feedback, метаданных, состояния сервиса и отчётов без базы данных. |

### URL и назначение endpoints

При стандартном запуске базовый адрес API — `http://127.0.0.1:8000`. Пути в таблице указываются относительно этого адреса.

| Метод | URL | Что принимает | Что делает и возвращает |
|---|---|---|---|
| `GET` | `/health` | Без тела запроса. | Проверяет готовность сервиса. Возвращает `status`, `model_loaded`, `model_version` и `training` — признак выполняющегося обучения. Если модель отсутствует или не загрузилась, возвращает статус **503**. |
| `POST` | `/predict` | JSON с полем `text`. | Анализирует отзыв активной моделью. Возвращает `criticality`, `label` и `confidence`. Версия модели передаётся в заголовке `X-Model-Version`. Запрос не добавляет отзыв в обучающие данные. |
| `GET` | `/models` | Без тела запроса. | Возвращает список сохранённых моделей: версии, признак активности, даты создания, версии датасетов, параметры обучения и доступные метрики оценки. |
| `POST` | `/load` | `multipart/form-data`: поле `model` — файл `model.joblib`, поле `metadata` — файл `metadata.json`. | Проверяет контрольную сумму и совместимость готовой модели, сохраняет и активирует её. Используется только для первоначальной загрузки, когда моделей на диске ещё нет. При успехе возвращает **201**, статус `loaded` и `model_version`. |
| `POST` | `/upload-dataset` | `multipart/form-data`: поле `file` — полный CSV с `text` и `label`. | Проверяет и сохраняет новую актуальную версию датасета. Возвращает **201**, статус `uploaded`, `dataset_version`, число отзывов `rows`, распределение `labels` и число сохранённых записей feedback `pending_count`. Модель не изменяется. |
| `POST` | `/feedback` | JSON с полями `text` и `label`. | Сохраняет новый размеченный пример или обновляет метку того же нормализованного текста в `feedback.csv` актуального датасета. Возвращает `id`, `label`, `dataset_version`, действие `added` / `updated` и число накопленных записей `pending_count`. Текущая модель не изменяется. |
| `POST` | `/train` | Необязательный JSON с параметрами `seed`, `c`, `max_iter`. | Объединяет актуальный датасет с feedback, разбивает данные на три выборки, обучает и оценивает модель. После сохранения новых версий данных и модели возвращает **201**: статус `completed`, версии, длительность, размеры выборок, метрики и построчные предсказания для validation/test. |

### Форматы основных запросов

**Анализ отзыва — `POST /predict`:**

```json
{
  "text": "Screen reader does not announce the login button"
}
```

Текст должен содержать слова или цифры и иметь длину не более 10 000 символов. Пустые строки и строки из одних пробелов не принимаются.

Значения в ответе связаны следующим образом:

| `label` | `criticality` | Значение |
|---|---|---|
| `no_issue` | `null` | Проблема доступности отсутствует. |
| `low` | `0` | Низкая критичность. |
| `medium` | `1` | Средняя критичность. |
| `high` | `2` | Высокая критичность. |

`confidence` — вероятность предсказанного класса, рассчитанная моделью, либо `null`, если оценка недоступна. Это не гарантия правильности предсказания.

**Сохранение исправления — `POST /feedback`:**

```json
{
  "text": "Screen reader does not announce the login button",
  "label": "high"
}
```

Допустимы только классы `no_issue`, `low`, `medium`, `high`. Отзыв может быть новым: его не обязательно предварительно отправлять на анализ или искать в исходном датасете.

**Повторное обучение — `POST /train`:**

```json
{
  "seed": 42,
  "c": 1.0,
  "max_iter": 1000
}
```

Параметры можно не передавать: будут использованы значения из примера. `seed` должен быть целым числом от 0 до 4294967295, `c` — конечным положительным числом, `max_iter` — положительным целым числом.

### Коды ответов

| Код | Значение |
|---|---|
| `200 OK` | Успешное предсказание, получение состояния или списка моделей, сохранение feedback. |
| `201 Created` | Успешная первоначальная загрузка либо завершённое обучение новой модели. |
| `404 Not Found` | Для сохранения feedback или обучения не найден исходный датасет. |
| `409 Conflict` | Попытка первоначального импорта при уже существующей модели либо повторное обучение, пока другое обучение ещё выполняется. |
| `413 Content Too Large` | Загружаемые файлы модели или метаданных превышают допустимый размер. |
| `422 Unprocessable Entity` | Ошибка входных данных, несовместимая модель, недостаток классов или конфликт разметки при подготовке выборок. |
| `500 Internal Server Error` | Внутренняя ошибка предсказания, записи feedback или обучения. Подробности записываются в логи сервера. |
| `503 Service Unavailable` | Модель не загружена: анализ недоступен, `/health` сообщает о неготовности. |

### Документация и проверка API

FastAPI автоматически предоставляет [Swagger UI](http://127.0.0.1:8000/docs), [ReDoc](http://127.0.0.1:8000/redoc) и [OpenAPI JSON](http://127.0.0.1:8000/openapi.json). Для проверки запросов в Postman можно импортировать [готовую коллекцию](postman/research-graph.postman_collection.json).

## Дополнительные команды проекта

Все команды ниже выполняются из корня проекта. Для подготовки данных и обучения через CLI запуск backend и frontend не требуется.

### Справка и конфигурация

| Команда | Назначение |
|---|---|
| `uv run rg --help` | Список общих команд проекта. |
| `uv run rg ml --help` | Список ML-команд. Для справки по отдельной команде добавьте `--help`, например `uv run rg ml train --help`. |
| `uv run rg version` | Версия установленного Python-пакета проекта. |
| `uv run rg check-config` | Проверка общих настроек и вывод их текущих значений. Токен GitHub выводится в маскированном виде. |

### Подготовка данных и обучение через CLI

| Команда | Назначение |
|---|---|
| `uv run rg ml audit --source data/raw/accessibility_reviews.csv` | Аудит исходного датасета со столбцом `review_text`: анализ структуры, очистка, поиск дубликатов и подготовка файла разметки. |
| `uv run rg ml audit --source data/reviews.csv --text-column text --output data/processed/audit-v2` | Аудит CSV со столбцом `text` с сохранением результатов в новый каталог. |
| `uv run rg ml annotate --review data/processed/audit-v1/review.csv` | Предварительная разметка английских отзывов по текстовым правилам. Предложения требуют проверки; спорные строки остаются без класса. |
| `uv run rg ml prepare --review data/processed/audit-v1/review.csv` | Разделение проверенных размеченных данных на train, validation и test с группировкой похожих отзывов. |
| `uv run rg ml train` | Обучение на `data/processed/split-v1/train.csv` и сохранение модели в `artifacts/baseline-v1/`. |
| `uv run rg ml train --source data/processed/split-v1/train.csv --output artifacts/baseline-v2 --seed 42 --c 1.0 --max-iter 1000` | Обучение с явно заданными путями, параметрами и новой версией модели. |
| `uv run rg ml evaluate` | Оценка модели `artifacts/baseline-v1/` на validation и test из `data/processed/split-v1/`. |
| `uv run rg ml evaluate --model-dir artifacts/baseline-v2 --split-dir data/processed/split-v1 --output artifacts/baseline-v2/evaluation` | Оценка выбранной модели на указанных выборках и сохранение отчётов в заданный каталог. |

CLI-команды не перезаписывают существующие выходные каталоги. Для нового запуска укажите другой путь через `--output`. Если используется другая версия аудита, передайте её каталог в `prepare` через `--audit-dir`, а каталог полученных выборок укажите в последующих командах обучения и оценки.

`audit` создаёт новый файл разметки с пустыми метками, даже если в исходном CSV уже есть столбец `label`. Для `prepare` заполните поля `label`, `reviewed` и `reviewer`. Если нужно обучиться на готовом полном размеченном CSV без этого промежуточного процесса, используйте загрузку через сайт и кнопку **«Обучить модель»**.

### Тесты и проверки кода

| Команда | Назначение |
|---|---|
| `uv run pytest` | Все Python-тесты с отчётом о покрытии. Минимальный порог покрытия — 70%. |
| `uv run pytest tests/backend` | Только интеграционные тесты backend. |
| `uv run pytest tests/ml` | Только тесты ML Pipeline. |
| `uv run ruff check .` | Проверка Python-кода линтером. |
| `uv run ruff format --check .` | Проверка форматирования Python-кода без изменения файлов. |
| `uv run ruff format .` | Автоматическое форматирование Python-кода. |
| `uv run mypy` | Статическая проверка типов Python. |
| `uv run pre-commit install` | Установка Git-хуков для автоматических проверок перед коммитом. |
| `uv run pre-commit run --all-files` | Ручной запуск pre-commit-проверок для всех отслеживаемых файлов. Хуки могут автоматически исправлять форматирование и отдельные ошибки. |
| `npm --prefix frontend test` | Запуск тестов пользовательских сценариев frontend. |
| `npm --prefix frontend run build` | Проверка TypeScript и сборка frontend для размещения. |

При запуске только части Python-тестов общий порог покрытия также действует: отдельные тесты могут пройти, но команда завершится ошибкой из-за недостаточного покрытия всего пакета. Для локальной проверки отдельного набора без сбора покрытия используйте, например, `uv run pytest tests/backend --no-cov`.
