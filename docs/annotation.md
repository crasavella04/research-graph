# Разметка критичности, версия 1

Метки тональности `sentiment` и факт обсуждения доступности `is_accessibility`
не определяют критичность. Положительный отзыв может содержать блокирующую
проблему, отрицательный — не содержать проблемы доступности.

## Классы

| label | criticality в будущем API | Правило |
|---|---|---|
| no_issue | null | Нет описанной текущей проблемы доступности: похвала, общий отзыв, исправленная проблема, пожелание без описанного затруднения |
| low | 0 | Небольшое неудобство; действие доступно без существенных затруднений |
| medium | 1 | Существенно затруднена конкретная функция; описан доступный обходной путь или частичное выполнение |
| high | 2 | Важное действие невозможно либо приложение недоступно при используемой вспомогательной технологии |

Оценивайте последствия из текста, а не эмоциональность, звёзды или наличие
ключевого слова. Просьба добавить night mode ради экономии батареи сама по себе
не доказывает проблему доступности. Отсутствие озвучивания кнопки входа,
из-за которого пользователь не может войти, — high. Классифицируйте наиболее
критичную из явно описанных текущих проблем доступности.

Если последствий недостаточно, не угадывайте класс: оставьте `reviewed=false`
и запишите причину в `notes`. Так же поступайте с неясным языком, спамом и
случаями, не укладывающимися в правила. Такие строки не попадут в выборки.
Для спорных случаев желательно независимое мнение второго разметчика.

## Порядок работы

1. Запустите аудит (команды в README). `review.csv` содержит уникальные отзывы.
2. Прочитайте полный `text`; заполните `label`, `reviewer` (имя/идентификатор
   человека), `notes` при необходимости. Только после проверки поставьте
   `reviewed=true`. Не меняйте `id`, `group_id` и `text`.
3. Одинаковый `group_id` означает потенциальные дубликаты. Проверьте их вместе.
   Разные классы внутри группы требуют разрешения конфликта. Если схожесть
   случайная и смысл различается, оставьте спорные строки непроверенными;
   алгоритм группировки консервативен.
4. Сохраните CSV в UTF-8 с исходными заголовками. Поля с запятыми должны быть
   корректно заключены в кавычки. После аудита файл не содержит меток.
   Необязательная команда `ml annotate --review <путь>` предлагает метки по
   английским текстовым правилам и помечает их `AUTO rules-v1` в `notes`.
   Она не использует sentiment, не отмечает отзывы проверенными и сохраняет
   резервную копию. Прочитайте текст и исправьте предложение перед подтверждением.
5. Выполните `ml prepare`. В каждую часть должны попасть все четыре класса.
   Нужны минимум три независимые группы каждого класса; это технический
   минимум, а не достаточный объём для оценки качества.

## Независимая оценка и воспроизводимость

Разбиение выполняется по проверенным меткам, со стратификацией по классам и
группировкой похожих текстов. Для каждого класса по 15% групп (округление вниз,
минимум одна) отводится validation и test; остаток — train. Доля строк может
отличаться из-за групп и малых классов. Seed по умолчанию 42.

После первой утверждённой разметки зафиксируйте версию split-каталога и не
меняйте test при настройке модели. Новые данные и исправленные метки требуют
новой версии; сравнение метрик разных тестовых выборок нельзя трактовать как
улучшение модели. Подбор параметров и обучение TF-IDF выполняются только
на train, выбор параметров — по validation; test открывается для итоговой оценки.

Группы строятся по Jaccard-сходству множеств слов >=0.85 для текстов с минимум
пятью уникальными словами; связанные пары объединяются транзитивно. Регистр,
Unicode-варианты и пунктуация игнорируются при поиске точных дубликатов.
Короткие тексты объединяются только при точном совпадении нормализованного ключа.
Это эвристика: семантические перефразы могут остаться незамеченными. Если позже
появятся достоверные идентификаторы приложений/авторов, следует добавить
группировку по ним для соответствующего сценария обобщения. `desc_id` нельзя
считать уникальным идентификатором отзыва без проверки.

Ручная проверка отмечается декларативно: программа проверяет поля, но не может
доказать, что человек действительно прочитал текст. Не выдавайте машинную
разметку за ручную. Для validation/test нужна независимая проверенная разметка.
Язык автоматически не определяется; по просмотренным примерам данные английские.
Русский язык не заявляется поддерживаемым.
